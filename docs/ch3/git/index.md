# Git 与平台协作导览

Git 是记录修改的工具，代码托管平台是围绕仓库开展讨论、评审和自动检查的协作空间。完成真实贡献需要同时理解两者。

## 必修路径

1. 理解仓库、提交、分支和远程仓库。
2. 配置 Git 身份和访问方式。
3. 使用 `git status` 和 `git diff` 判断当前状态，用 `git add` 选择变更。
4. 分支创建与同步：用 `git switch -c` 创建个人分支，并与远程保持同步。
5. 形成聚焦的提交并读懂 CI 结果：写清提交动机，读懂 Checks 与 Actions 日志。
6. 在个人分支上修改，通过 Fork 或项目分支提交 Pull Request，并根据评审意见继续更新同一分支和 Pull Request。

## 最小安全习惯

- 执行修改历史或工作区的命令前，先运行 `git status`。
- 不把密码、令牌、私钥或个人敏感信息提交到仓库。
- 不对共享分支执行变基或强制推送。
- 不盲目运行项目中的脚本，先阅读贡献指南和脚本内容；不要运行 `curl ... | bash` 这类把网络内容直接交给 shell 的命令。
- 提交前用 `git diff --staged` 复核暂存区，确保没有夹带密钥、构建产物或无关修改。

## 拓展路径

完成首次贡献后，再根据需要学习 rebase、对象数据库、复杂分支策略和邮件列表补丁流程。工具掌握的目标不是记忆命令，而是能解释每一步对仓库历史和协作对象的影响。
